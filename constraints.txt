# Resolver constraints applied when compiling requirements.lock / requirements-dev.lock.
# Not installed directly — see docs/DEPLOYMENT.md.
#
# torch is not a direct dependency; it arrives transitively through
# sentence-transformers, and pip would otherwise resolve it to the newest release on
# PyPI. That breaks the GPU path in a way that is silent and easy to miss:
#
#   - the setup scripts install a CUDA build first, from the cu128 wheel index
#   - installing the lock afterwards finds a *different* torch version pinned
#   - pip replaces the working CUDA build with the CPU build from PyPI
#   - torch.cuda.is_available() goes False, and the only symptom is that everything
#     got slower
#
# Measured 2026-08-16: https://download.pytorch.org/whl/cu128/torch/ publishes
# cp312/win_amd64 wheels up to 2.11.0, while an unconstrained resolve chose 2.13.0.
# Capping below 2.12 keeps the locked version one the CUDA index can actually serve, so
# CPU and GPU installs run the same torch version and differ only in build.
#
# Raise this ceiling when the cu128 index publishes a newer wheel, and re-run:
#   uv pip compile requirements.txt     -c constraints.txt -o requirements.lock
#   uv pip compile requirements-dev.txt -c constraints.txt -o requirements-dev.lock
torch<2.12

# CVE floors, added 2026-11-07. These three arrive transitively — aiohttp via
# kubernetes/langchain-community/voyageai, filelock via huggingface-hub/torch,
# oauthlib via requests-oauthlib — so there is no range of ours to widen. Without a
# floor here the fix is recorded nowhere: `uv pip compile` prefers whatever is already
# in the lock, so today's pins survive a relock by accident rather than by intent, and
# a from-scratch resolve would quietly reintroduce the vulnerable versions.
#
# Trivy, 2026-11-01, on the CPU image: 55 findings, 49 HIGH + 6 CRITICAL.
#   aiohttp  < 3.14.4  CVE-2026-111064, CVE-2026-111066  HIGH      denial of service
#   oauthlib < 4.0.0   CVE-2026-118669, CVE-2026-49272   HIGH      privilege escalation
#   filelock < 4.2.1   CVE-2026-112940                   HIGH      arbitrary file overwrite
#
# pillow is NOT here on purpose: it is a direct dependency, so its floor belongs in
# requirements.txt, which now reads pillow>=13,<14 (was <13, which forbade the fix for
# two CRITICAL heap overflows).
#
# Drop a line from this list only when every parent's own range has caught up, so the
# resolver would pick the safe version unaided.
aiohttp>=3.14.4
oauthlib>=4.0.0
filelock>=4.2.1
